# Техническое задание и план: «Формирование документов по шаблону» для 1С:Бухгалтерии

## 1. Цель

В разделе **Банк и касса → Платежные поручения** нужна кнопка **«Сформировать документ»**. По ней пользователь выбирает документ из списка шаблонов (первый шаблон — договор процентного займа) и получает файл Word, заполненный данными платежного поручения.

Дополнение должно:
* устанавливаться в любую базу 1С:Бухгалтерии 3.0 без изменения типовой конфигурации (обновления 1С продолжают ставиться как обычно);
* пополняться новыми шаблонами без программирования.

## 2. Выбранное решение

| Вопрос | Решение | Почему |
|---|---|---|
| Тип дополнения | **Расширение конфигурации (.cfe)** | Устанавливается из режима Предприятия, не снимает конфигурацию с поддержки, переживает обновления БП. Расширение даёт свою кнопку и хранит шаблоны в базе. Внешняя печатная форма (.epf) дала бы только пункт в подменю «Печать», без отдельной кнопки и без справочника шаблонов. |
| Язык | **Встроенный язык 1С** (код расширения) | Работает внутри 1С на любом компьютере, где есть 1С. Не нужны Python, Word или другие программы на сервере. |
| Формат шаблона | **Word .docx с полями `{{Имя.Поля}}`** | Шаблон готовится в обычном Word. Документ заполняется без Word: программа распаковывает .docx (это ZIP) и заменяет поля в XML. Работает и на сервере без MS Office. |
| Хранение шаблонов | **Справочник в базе** | Шаблоны доступны всем пользователям базы на всех компьютерах. Новые шаблоны добавляются из интерфейса. |
| Python | Только для разработчика | Скрипты сборки и тестов (`tools/`, `tests/`). Пользователю не нужен. |

## 3. Состав расширения «ШаблоныДокументов» (префикс объектов `ШД_`)

| Объект | Назначение |
|---|---|
| Общая команда `ШД_СформироватьДокумент` | Кнопка «Сформировать документ» в списке и в форме платежного поручения (параметр — ДокументСсылка.ПлатежноеПоручение). Типовые формы не изменяются: команда попадает в группу глобальных команд формы. |
| Общая форма `ШД_ФормированиеДокумента` | Выбор шаблона, таблица полей с автозаполненными значениями (можно править), кнопки «Сформировать и открыть», «Сохранить в файл...», ссылка «Шаблоны документов...». |
| Справочник `ШД_ШаблоныДокументов` | Шаблоны: наименование, файл .docx (хранилище значения), шаблон имени файла, описание, табличная часть «Параметры» (имя, представление, значение по умолчанию, запоминать). Форма элемента: загрузка/редактирование/сохранение файла, поиск параметров в шаблоне, справка по доступным полям. |
| Регистр сведений `ШД_ЗапомненныеЗначения` | Исправленные пользователем значения (ключ: организация / контрагент / шаблон + имя поля). |
| Общий модуль `ШД_ФормированиеДокументов` (сервер) | Сбор данных, вычисление полей и модификаторов, заполнение .docx, запоминание значений, поставляемые шаблоны. |
| Общие макеты `ШД_ПоставляемыеШаблоны`, `ШД_Шаблон_ДоговорПроцентногоЗайма` | Описание и файл поставляемого шаблона. Шаблон создается в справочнике при первом открытии формы. |
| Заимствованные объекты | Документ `ПлатежноеПоручение` (тип параметра команды), роль `БазовыеПраваБП` (права пользователей на объекты расширения), язык `Русский`. |

## 4. Функциональные требования

1. Кнопка «Сформировать документ» доступна в списке платежных поручений и в форме платежного поручения.
2. Окно формирования:
   * показывает платежное поручение и шаблон (по умолчанию последний использованный);
   * показывает **все поля выбранного шаблона** с рассчитанными значениями и позволяет их исправить;
   * выделяет исправленные значения и позволяет вернуть рассчитанное значение;
   * подсвечивает поля, требующие внимания: красным — пустые; жёлтым — значения по умолчанию, автоматическое склонение, руководитель из контактных лиц, параметры с флажком «Выделять для проверки»; зелёным — ранее исправленные пользователем. Показывает пояснение и итог «Требуют внимания: …»;
   * запоминает исправления реквизитов организации/контрагента для следующих документов (флажок);
   * формирует .docx и открывает его или сохраняет в выбранную папку;
   * сообщает о незаполненных полях.
3. Источники данных:
   * **платёжное поручение** (первичный источник): номер, дата, сумма, ИНН/КПП плательщика и получателя, банковские счета сторон;
   * по платёжке определяются организация (Заимодавец) и контрагент (Заёмщик), **из их карточек** берутся наименование, ОГРН, ОКПО, адреса, руководитель. Руководитель организации — «Ответственные лица», руководитель контрагента — «Контактные лица» с должностью директора или руководителя (в типовой карточке контрагента БП поля «Руководитель» нет);
   * карточка договора из платёжки — только запасной источник подписантов;
   * условия нового договора (номер и дата из даты платёжки, ставка, срок) — значения по умолчанию из настроек шаблона, всегда подсвечиваются для проверки;
   * для каждого поля показывается источник (колонка «Откуда взято»), а для пустых — где его заполнить в 1С. Из окна открываются карточки организации, контрагента и договора, есть кнопка «Обновить данные»;
   * ручное исправление запоминается с привязкой к исходному значению из 1С: если карточку заполнили или изменили, приоритет у карточки.
4. Шаблоны:
   * поля `{{Имя}}` и модификаторы `{{Имя|ВРЕГ}}`, `{{Дата|+4Г}}`, `{{Дата|ДФ=dd/MM/yy}}`, падежи и т. д.;
   * поля, которые Word разбил разметкой, распознаются;
   * поля в колонтитулах и сносках заполняются;
   * поля, которых нет среди стандартных, становятся параметрами шаблона со значением по умолчанию (выражение с вариантами через `||`).
5. Поставляемый шаблон «Договор процентного займа» создаётся автоматически.

### Сопоставление полей договора займа (по образцу)

|---|---|

## 5. Нефункциональные требования

* Совместимость: 1С:Бухгалтерия предприятия 3.0, режим совместимости расширения 8.3.27 (проверено на БП 3.0.205.22, платформа 8.5.1.1529).
* Клиент: файл формируется на сервере и передаётся на компьютер пользователя через временное хранилище (механизм БСП «ФайловаяСистемаКлиент»), поэтому решение подходит для тонкого и веб-клиента. Проверено в клиенте 1С:Предприятия 8.5 на файловой базе.
* Расширение должно быть подключено **без безопасного режима**: в безопасном режиме платформа запрещает временные файлы, нужные для работы с .docx. При включённом безопасном режиме пользователь получает понятное сообщение с инструкцией.
* Права: через заимствованную роль «БазовыеПраваБП» (есть у всех пользователей БП).
* Стабильные идентификаторы объектов при пересборке: обновление расширения не теряет шаблоны и запомненные значения.

## 7. Ограничения и возможные доработки

* Документ формируется по одному платежному поручению. Можно добавить пакетное формирование для нескольких выделенных платежек.
* Можно добавить автоматическое прикрепление сформированного договора к платежке (присоединённые файлы) и сохранение в PDF (потребуется Word/LibreOffice на сервере).
* Можно поддержать другие документы-основания, например «Списание с расчетного счета» и «Счет на оплату». Для этого достаточно расширить тип параметра команды.
* Для других конфигураций (УТ, КА, ERP) нужна адаптация: там другой документ платежа.
* В тестовой базе установлено расширение «РасчетыПроцентовПоЗаймам». Конфликтов нет, но при развитии темы займов можно брать ставку или график из его данных.

## 8. Для разработчика

```
python tools/make_loan_template.py      # пересоздать шаблон договора из Образцы/*.docx
python tools/build.py                   # сгенерировать XML расширения в build/extension
python tools/build.py --cfe --update-db # + загрузить в тестовую базу и собрать dist/ШаблоныДокументов.cfe
python tests/run_tests.py               # сборка + интеграционные тесты на копии базы
```

Параметры тестовой базы находятся в `tools/build.local.json`. Новый поставляемый шаблон добавляется так: файл `.docx` кладётся в `src/templates`, его описание добавляется в `src/templates/templates.json`, затем расширение пересобирается.
